# Spec r2: autonomous reconciliation, settlement and bounded recovery

Status: draft for independent review; not an execution baseline. Date: 2026-10-07.
Authoritative store: this GitHub issue in `axatbhardwaj/axstack`. Approval will bind its exact body SHA-256, recorded separately so the body does not hash itself. Private evidence and machine paths remain private.

## Outcome and evidence

An authorized T3 driver continues eligible work without repeated phase-start requests, settles accepted completions, reconciles interrupted operations, and stays silent during healthy unchanged waits. The user still receives requested status answers and notifications allowed by the existing policy.

Baseline inspected: installed Axstack 0.27.4 and source main `8ac647f4b6dca3c2cc4766d86484cfca5d6a2041`. Source and installation equivalence must be verified for changed files before implementation; release execution rechecks its actual base.

The last-month audit found 249/563 completed delegated threads unsettled and 277/2747 repeated-wait messages across 15 drivers. Acceptance eligibility and requested-status provenance were not established for those totals. They are investigation signals, not violation or avoidable-noise rates. Of 671 threads, 618 were created October 5–7; this is not a balanced month sample. Existing policy already requires acceptance, settlement/readback, same-turn continuation, bounded lost-launch reconciliation, and protected-state holds. The confirmed textual ambiguity is that watch-runtime conditions silence on no unsettled runs.

## Design

**Usage:** The original authorized driver handles a T3 wake, resume, or completion; reconciles its own approved run; continues every eligible next action; and emits no automatic waiting update when nothing reportable changed.

**Shape:** T3 native state → existing acceptance/settlement predicates → verified operation result → authorized continuation. Existing Markdown references own policy; the private run record stores evidence pointers. No new service or runtime state machine.

**Binding:** Native project/task/thread/run/attempt identities, exact revisions, owner, role snapshot and approved authority. For settlement recovery, record pending intent and consumed allowance before issuing the call, then its native result/readback. Existing launch, send and schedule receipt requirements remain unchanged; this is not a journal for all mutations. Use request IDs only where supported. A record entry is not proof an action happened.

**Flow and failure:** Reconcile local work even when the forge digest is unchanged. Consume completed work under current acceptance rules, settle eligible threads, read back state, then advance authorized dependencies in the same turn. A lost reply first triggers native readback; an observed effect is adopted without re-execution. Unknown liveness or effect holds its dependants. Known failure stays incomplete and is classified before any existing replacement route is considered.

**We accept:** bounded uncertainty holds where native evidence cannot prove safe continuation; fewer automatic messages while work is genuinely unchanged. **Rejected:** blanket retries, invented exactly-once guarantees, broad cleanup, replacing existing policy with a new dispatcher. **Open:** native operation behavior remains to be verified under the acceptance scenarios below.

## Bounded recovery contract

1. Reconcile pending effects before repeating anything. `settled:true` is adopted with no settle call, no second acceptance and no duplicate downstream dispatch; any still-unperformed authorized next action proceeds. Re-read native state and the shared settlement guards even when the forge digest is unchanged.
2. For a matching accepted completion whose thread is `settled:false`, positive evidence that the driver has not issued settlement permits the first settle under existing authority. Missing logs alone are not such evidence: an interrupted pending intent is an uncertain prior call. If an earlier settle succeeded, errored, timed out or lost its reply, reconcile its outcome first. A plain `settled:false` snapshot, a returned timeout, or absence of a request ID does not prove non-application or that an old request can no longer apply.
3. The only new retry allowance is one additional `t3_thread_organize(action: settle)` execution after an explicit transport failure or lost response for that settlement. Qualifying observations are a connection reset/closed connection, MCP transport-unavailable error, timeout with unknown application, or an interrupted driver with an evidenced issued call but no response. None establishes retry safety on its own. Exclude every protected failure in paragraph 8. Retry only after fresh shared settlement eligibility checks and either definitive native non-application evidence or native-verified idempotent settlement behavior for the same unchanged accepted completion. The prior request must be finished or proven unable to affect a later/current run; unresolved in-flight state holds. If the native interfaces cannot establish these conditions, perform read-only reconciliation and retain the hold.
4. Allowance identity is the original dispatch key plus accepted terminal run ID and candidate head (or report-only source identity), bound to its thread. Persist consumption before issuing the additional call. Wakes, compaction, request-ID changes, and replacement attempts cannot reset the allowance for that same completion. A genuinely new accepted repair/replacement completion has its own identity and allowance; it cannot be fabricated to bypass a held operation. Merge/close settlement uses the last accepted completion's existing allowance, not another one. This spec does not authorize recovery of a failed writer by resuming its failed thread.
5. A second failed or ambiguous execution holds that dispatch's advancement and never causes source repair. Record the operation, consumed allowance, reason and resume condition. A new or materially changed hold is reported once in the driver thread; unchanged holds are not repeated automatically. Requested status answers name the hold. Resume when fresh native evidence establishes the operation succeeded and guards remain valid, or when the user resolves a decision within existing authority. Relay only under existing decision/serious-risk categories; a metadata hold is not automatically a user decision.
6. Existing writer-launch recovery retains full inventory, exact identity/worktree proof and one relaunch on proven absence. For a lost delegated-launch response, reconcile the recorded request and fully paginated exact-title/project/parent/role/attempt evidence: adopt one exact matching task only if native task identity and configuration are verified; otherwise hold with read-only reconciliation. For a lost queued-send response, use the exact target thread, message/request receipt and resulting run evidence; a matching thread title alone is insufficient. Adopt a proven delivered effect, otherwise hold. Neither case gains resend authority.
7. No new automatic retry authority covers writer launch/send, source edits, publication, merge, tags, installation or deletion. Known failed writers remain incomplete and follow existing permission, ownership, descendant/liveness, same-author/replacement and applicable goal/review/lost-launch rules. These distributed checks are preserved, not replaced by a new cause gate or universal replacement budget. Unknown liveness forbids replacement. Missing notification alone proves neither failure nor absence.
8. Keep repair rounds, debug fix attempts and lost-launch limits distinct and preserved across resumes/replacements. Denial, refusal, permission/trust/hook/auth/model prompts, unavailable model, quota holds and explicit user stops are never transient errors to bypass. Preserve existing approved same-provider account selection separately.
9. A healthy unchanged wait requires positively known active work, no unconsumed terminal receipt, no actionable next step, no new question/permission request, and no unresolved failure or liveness/coverage uncertainty. Silence follows reconciliation, never substitutes for it. Held/unknown work is not labelled healthy; its reporting and resume rules above apply. Existing watch cadence stays unchanged.

### Evidence classes and test isolation

The user selected **labelled simulation plus real T3 checks** for transport-failure recovery. `N` means observed native T3 behavior; `R` means a controlled decision replay/fixture with labelled injected inputs; `S` means semantic/source checks. A composite result does not turn R into proof of a real outage.

| Coverage | Required evidence |
|---|---|
| AC1 | N: two actual scheduled wakes, active worker state, output/relay counts and retained watch; N: requested status answer. R: held/unknown negative classification. |
| AC2 | N: one controlled completion scenario plus duplicate delivery/repeated observation showing one native downstream action. S: same-turn continuation rule. |
| AC3 | N: initial settle, settled-state adoption, readbacks, and idempotency characterization if used. R paired with those N operations: never-issued, connection failure/lost response, eligible retry, exhausted allowance and unknown in-flight branches. No actual transport outage is required or claimed. |
| AC4/AC5/AC9 | S and non-mutating R for unsafe protected/denied/foreign/user-takeover and failure-budget branches. N on disposable owned resources for successful identity adoption and completion guards. Never create a real unsafe or denied operation to test refusal. |
| AC6 | N for duplicate-effect observation; R for driver interruption/resume, compaction-equivalent retained record, allowance exhaustion, new accepted repair and merge/close identity. S for preserved phase counters. |
| AC7 | Reconciled calculations from the retained N/R records, clearly separated by evidence class; missing production baseline remains UNKNOWN. |
| AC8 | S: real pre-change semantic red/green, in-memory mutations/rewordings, full suite and diff check logs. |

Canary threads read the exact candidate skill/reference bytes from a pinned detached checkout, explicitly as a test-only override of installed reference selection. They do not install skills or edit live home configuration. Record candidate SHA, referenced file hashes, thread/run identities and this override in their briefs. The production driver continues to use installed instructions; the override grants no production mutation or recovery authority.

Use isolated resources and schedules owned by this run; retain task/run/action IDs, terminal state, readbacks and observable output. Controlled replay may discard a disposable call's response or inject a transport result into the test decision trace, then pair it with actual native settlement/readback. It must never be described as an actual network outage. An idempotency canary characterizes the observed same-completion behavior only; it does not prove race safety for an in-flight request or changing run. Native guards and absence of unresolved work remain mandatory.

Teardown settles and archives only accepted eligible canary resources, deletes owned schedules by exact ID and verifies absence, and preserves evidence before removing owned checkouts. No real user-taken-over/foreign resources or T3 database are mutated. Each clause is PASS only with its declared evidence class; absent required N or R evidence is UNKNOWN and holds that acceptance. A scope reduction or evidence-standard change requires an approved revised baseline.

## Exclusions and decisions

No failed-writer automatic resume, cross-run backlog cleanup or abandoned-driver takeover; no new daemon, scheduler, database, general retry engine or runtime state machine; no model substitution, relaxed permissions, review-verdict reuse after changes, retry-budget reset or automatic unsafe recovery. No changes to the PR statistics visualization are included.

Design comparison selected the reconciliation-first candidate, adding explicit completed-unconsumed classification and open measurement intervals. Broader universal retry budgets, unconditional writer replacement, action-key-only success claims and assumed audit violation rates were rejected.
