# Anatomy skill, archify removal, visual Explain — execution baseline r10

Repository axatbhardwaj/axstack. Base main c0c0f54b0238bc3057c8df23e030ada6c67938dd. Run 20261012-explain-anatomy.
User authority (2026-10-12): vendor anatomy as its own skill; remove archify and simplify Explain in the same PR; in `mixed`, visuals are always authored by Sonnet 5.5 and reviewed by Sol; single-provider presets keep their own pairs; release under AGENTS.md standing authority; the user approves the npm stage.

## Outcome
- New skill `axstack-anatomy` carries the vendored [anatomy](https://github.com/wheresryan22/anatomy/tree/689dcf966e63d92be10a5d593c6e19e10acd4422) code (MIT) for crafted isometric figures, used only on explicit request.
- archify is retired: no provisioning, no viewer route, no docs promise. Only a legacy-release compatibility surface remains (D1).
- Explain helps the user pass the whiteboard defense: after an explanation of a whole system, PR, run or change (shipped, in review or planned), the user can explain it at a high level and defend its decisions without line-level detail. Explain's other uses (narrow questions, gap reports, blast radius, spec readbacks, show-your-work) stay.
- `axstack-diagram` folds into `axstack-explain`. Explain picks the best visual for the concept (flowchart, sequence, state, architecture map, timeline, comparison, or a new bespoke SVG); forms are examples, not a taxonomy.
- Every visual Explain delivers (inline page, chat Mermaid, anatomy figure) is authored by `axstack-explainer` and reviewed by `axstack-explainer-review`. In `mixed` the author is pinned to `claude-sonnet-5-5` high and the reviewer is codex Sol. `codex-only` and `claude-only` keep their provider/model/effort pairs.
- Plain-prose answers stay driver-written. Only the driver calls `html_render`. Cost: most Explain answers now take at least an author and a reviewer dispatch, whiteboard-defense answers in chat also get a reviewer dispatch, and anatomy pages also need a verifier run. The PR body discloses this.

## Decisions
- D1 Legacy archify: delete provisioning, pin, record write, `ARCHIFY_*` env, check row, smoke and provisioning tests. Keep one legacy module that releases a previously recorded copy on upgrade and uninstall through the existing transactional owner-release path: release only this skills root; delete only an unchanged real directory at the recorded SHA with no remaining owners; keep path/symlink guards and owner rollback on manifest-write failure; an edited or unowned `archify.json` is preserved. The manifest parser accepts the legacy `archify` field; new manifests omit it. `--tools-dir` is an explicit obsolete-flag error like `--profile`. Retained copies are reported with a reason. The legacy module keeps only local read-only Git checks (`rev-parse`, `status --porcelain --ignored`) and no network.
- D2 Skill shape: remove `skills/axstack-diagram`. Explain absorbs its general fidelity rules (source mapping, claim labels, planned/unknown marking, text alternatives, accessibility) and Mermaid rules (accTitle/accDescr, no theme init, split large views), drops archify schema text and the archify 700-word-cap card exemption, takes over diagram/visualize/draw triggers, and routes a stale `axstack-diagram` install here (like the `axstack-docs` line). Diagram's ideas credit moves to Explain (update the structural-test special case). The release PR body (the release notes) names the removed `/axstack-diagram` entrypoint and the `--tools-dir` obsolete error; the npm-stage decision message to the user repeats both. Shipped skill count stays 18 (−diagram, +anatomy).
- D2a Whiteboard defense: applies when the user asks to understand or defend a whole system, PR, run or change (triggers include "help me defend X", "whiteboard defense for PR N", "prep me for questions on X"); narrow questions stay proportional. Explain §2.1's primary-view list (purpose, rationale, alternatives, boundary, status and uncertainty, reader questions) stays the base for every explanation; inside D2a's scope the five elements extend it, and §1.6's decision trail is the evidence source for (2). On conflict, the spec-readback identity rules win when defending a spec; a show-your-work or blast-radius request keeps its own rule unless the user also asks to understand or defend the whole. The explanation covers, from inspected evidence with claim labels: (1) how it works at a high level and where data flows (a whiteboard-redrawable visual is optional under D2); (2) key decisions as "why X instead of Y"; (3) main data structures or state and why; (4) what happens if a user, dependency, agent or attacker misbehaves or acts maliciously; (5) where it fails and how that failure shows. Traced means source, tests, observation or recorded design (spec, run-record Decisions, ADR, PR); each claim carries its §1.3 label, and design-only claims are planned/proposed; for shipped or in-review work a design-only (4)/(5) claim also lists "implementation not traced" as an open gap. A missing alternative, reason or data-structure rationale, and any misbehaviour or failure not traced, is listed as an open gap, never invented. (4) names each trust boundary on the flow traced in (1) with an evidence pointer (an unclear boundary is an open gap) and covers the actors crossing them; any actor the user names is answered or listed open; the explanation says in one line that other actors are out of scope. (2) and (3) may be omitted only as "does not apply" with a one-line reason and evidence pointer; (1), (4) and (5) are never omitted, only answered or open. None is dropped silently. It closes with likely whiteboard questions beyond (1)-(5) plus the open gaps, one line each: each question gets an evidence-backed, labelled answer or is marked open; an open gap names the missing evidence and says the user should resolve it before defending the work. A D2a explanation is a consequential claim under Explain's review rule (in chat too). (5) does not trigger the blast-radius proof; that runs only on "what could this break". Function names and line-level detail appear only as evidence pointers. If the five elements and closing questions cannot fit in 700 words, explain the top level, keep every element and the open gaps as at least one line each, move closing questions that do not fit into the offered per-component explanations and say how many moved; none is dropped silently. If even the mandatory lines exceed 700 words, give the top-level explanation first and split the rest into per-component explanations; the cap is never exceeded. For work the user or its records (a run record, spec, PR body or README that states it) identify as a PoC, demo or experiment, the checklist is optional, the answer stays proportional and follows Explain's ordinary review rule (the full D2a applies if the user still asks for the checklist); the agent never infers that status, and a stated intent to ship overrides it.
- D3 Authoring and review: the selected preset's `axstack-explainer-review` is the reviewer everywhere (Sol in mixed); review of consequential or complex claims in driver-written prose is unchanged, except that every D2a explanation counts as consequential. Explain dispatches each visual it delivers to `axstack-explainer` with a bounded evidence brief; `axstack-explainer-review` always reviews the exact final bytes before delivery; any byte change invalidates review. The "consequential or complex claims only" condition is removed for visuals. The claude-only separate-session permission (Sonnet author high, Sonnet reviewer high, session independence only, no cross-provider claim) is kept and covers every visual. Mermaid owned by other phases (e.g. design-lens sketches) follows its own owners; README/docs diagram edits go through Implement under Explain's Mermaid rules. Any rule that chat Mermaid or chat diagrams need no dispatch is removed. Preset notes in all three presets become "authors every visual Explain delivers" / "always reviews every visual"; providers, models and efforts change only for the mixed pin.
- D4 Fallback order (one rule): if the reviewer seat is unavailable, a D2a explanation is held and the reply names the unavailable reviewer; it is never delivered unreviewed. A D2a explanation still failing review after two repair rounds with the same author is held and names the unresolved findings; it is never delivered as reviewed. A missing preview or render tool, an unavailable verifier or check, or a page absent after an ambiguous `html_render` is handled like an unavailable seat: the page is held and the answer is plain prose naming it (D2a prose is still reviewed). Otherwise: an unavailable required author or reviewer seat holds the visual and the answer is plain prose naming the held visual; a visual still failing checks after two repair rounds with the same author is replaced by plain prose with the reason; an anatomy page above the size cap is delivered per D7. The previous unreviewed "chat with Mermaid" fallback is removed; the driver never writes a substitute visual.
- D5 Inline pages: existing rules stay (self-contained, no network, 700-word cap, exact-bytes scan, driver-run gating previews at 728 dark/360 light, ui-verifier for interactive pages, driver-only `html_render`). Author `html_preview` calls are optional self-checks.
- D6 axstack-anatomy front door: an Axstack-owned `SKILL.md` with an explicit-request-only description (isometric / physical-object / anatomy figure). Direct `/axstack-anatomy` use follows Explain's dispatch, review, preview and delivery and never builds in the driver thread. Upstream `SKILL.md` is kept byte-identical under a non-`SKILL.md` name as reference and cannot re-enable automatic selection. Vendored tree: kit/, scripts/, references/, example build sources, README, CHANGELOG, LICENSE, provenance note (repo, full SHA, MIT). Not vendored: prebuilt `examples/**/*.html`, CODE_OF_CONDUCT, CONTRIBUTING, SECURITY, `.github`, `.git*`, `agents/`, `evals/`, `tests/fixtures/`. Modified upstream files are enumerated in a source-proof manifest with hashes (expected: README.md dead links and `~/.agents` path, scripts/capture.mjs and scripts/drive.mjs `C:\` references); every other vendored file is byte-identical to upstream, including examples/ripple-tank/build.mjs, whose `orca` substring hit is a false positive handled by a narrow identifier exemption. The manifest records the upstream git blob SHA and the current SHA-256 per vendored file; a test recomputes blob SHAs for unmodified files and asserts the on-disk vendored file set equals the manifest set; one-time evidence diffs the manifest against `git ls-tree -r 689dcf9` minus the exclusions.
- D7 Size cap: count final UTF-8 page bytes; cap = 512,000 (the `html_preview`/`html_render` `maxLength`). At or below the cap the page is inline. Above it (anatomy only), the page keeps exactly the same author/reviewer bindings as inline delivery and gets the exact-bytes network scan, the `axstack-explainer-review` review, and a ui-verifier pass that serves the exact bytes on loopback and emulates `prefers-color-scheme` dark and light at 728 and 360 in the verifier's configured browser (Playwright MCP in this run; never T3 `preview_*`); it is saved to `~/axstack-pages/<run>/<name>.html` on the driver host, and the reply gives that host-local path with a short chat summary. Oversized pages follow the inline-pages rules (700-word cap, exact-bytes scan, D8 theme) except `html_preview`/`html_render`. The saved file's SHA-256 equals the reviewed SHA-256. Files under `~/axstack-pages/` are kept until the user removes them. No hosting, no remote resources.
- D8 Anatomy execution boundary: Bun only. A build copies kit/, `scripts/inline-kit.mjs` and the figure directory into the dispatch scratch folder with the same layout and builds there; the installed skill tree is never written (tree hash unchanged). Upstream Chrome-spawning scripts (`capture`, `drive`, `lines`, `turn-check`, any `node:child_process` use) and the React examples (spot-plate, test-rig) are retained but marked unsupported; rendered checks go through the configured verifier. The front door overrides upstream's gates: run `--audit` under Bun when the figure uses audited parts and record result and time; upstream's line-end check is a named unproven gap covered by verifier close-ups. The explainer returns the size class and time estimate first; the driver asks the user before building above Figure size. Theme wrapper: one named shipped JS file at the `skills/axstack-anatomy/` root, outside vendored directories (linted, strict-TDD `bun:test` red first), injected verbatim into the page. An explicit user theme request sets a dedicated `data-axstack-theme` marker; the wrapper ignores the `data-theme` the anatomy build writes, and the marker wins inside T3 and standalone. Inside T3 it reads `--background` luminance (any CSS color syntax) on load and on change, sets anatomy's `data-theme`, and neutralizes anatomy's page background and outer margins (zero-gutter, no-background rules). When `--background` is absent (standalone file) it honors the marker, else `prefers-color-scheme` with live changes, and restores a self-contained page background. Anatomy's figure card stays as an inner panel; inline-pages.md states this exception.
- D9 Repository boundary: one shared vendored-path constant feeds repository test exemptions; each exemption stays at the narrowest content scope (no blanket exemption from forbidden or retired-reference scans). Root `bunfig.toml` `[test] pathIgnorePatterns` excludes vendored `*.test.mjs` and biome ignores exactly the vendored paths; a contract test asserts both configs match the shared constant. Packaged prose budget excludes vendored upstream Markdown (loaded on demand as reference); the front-door SKILL.md counts. The 387,533-byte ceiling stays, or rises only by measured bytes with a history line in `prose-size.test.js`. Any global Bun test-timeout change is replaced by a per-test timeout. AGENTS.md replaces the archify exception with (a) a narrow anatomy exception (vendored Node-oriented code run with Bun, no installer network or Git step) and (b) the legacy archify release's local read-only Git checks; a prose-contract test replaces `archify-exception.test.js` for (a) and (b).
- D10 PR shape: one PR, sole author = existing `t1-anatomy-a1`, re-baselined to this plan: the final `skills/axstack-anatomy` tree arrives in one bulk vendored commit (no add-then-move, superseded opt-in Explain route commit dropped); later commits contain only the D6 edits and exemptions; other commits about 200 lines, semantic messages. Package grows from about 0.78 MB to about 2.5 MB unpacked (disclosed).
