# Stable T3 and Omarchy appearance — proposed r2

Scope: Axstack and Haoshoku use T3 stable by default; Omarchy desktops receive a one-time match to the current Omarchy palette. User confirmed both repositories and explicitly deferred automatic theme synchronization. Existing docs/specs convention is the proposed GitHub repository-document store; this private draft is not yet an approved baseline.

1. Axstack: use stable 0.1.0 as the documented and checked minimum. Checks distinguish stable from nightly and report actionable remediation for prereleases; no automatic installation or channel mutation in capability checks. Update affected verification recipe and behavioral tests. Preserve historical specs.
2. Haoshoku: desktop packages, managed primary-app defaults, Super+T recipes, CLI linking, Debian installation and update-channel setup target stable. Preserve unrelated custom primary apps and unmanaged executables; detect old managed nightly choices and replace only proven Haoshoku-owned defaults/links. An unmanaged nightly or a running version newer than stable gets a clear bounded migration hold rather than silent downgrade. Reruns must not select nightly again. Keep existing tailnet access and single-server ownership.
3. Theme: import/select the existing Omarchy palette once on the stable T3 desktop through supported theme configuration. Keep Local environment disabled where the standalone service owns the backend. Do not promise automatic theme sync: the user deferred it after the T3 primary-environment limitation was verified. Preserve the current Omarchy theme, unrelated T3 preferences and provider settings; do not create a second server or daemon. No Android or browser theme changes. If native theme import cannot be automated safely, provide the importable palette and exact manual step, and report that step as pending rather than success.
4. Verification: meaningful Bun behavioral red/green checks in temporary homes; installed-package/CLI smoke checks; fixtures for existing managed nightly links/defaults, custom app preservation, stable reruns, wrong channel and failed setup; one-time theme import/selection and rerun behavior (no automatic sync). Verify a real stable desktop via Playwright where available and retain explicit evidence if desktop-specific appearance cannot be proved. Confirm actual CLI and running server versions separately, thread resume, Codex/Claude delegation, scheduled/PR wake behavior and Android connection before fleet completion. Human phone verification may remain a named checkpoint.
5. Authority and delivery: Repository changes and the one-time palette choice are requested. Axstack release/four-host reinstall has standing authority. T3 fleet channel migration, Haoshoku release/install and live desktop theme application are proposed checkpoint scope requiring user approval of this revision before host writes. Delivery: independent repository PRs with cross-provider authored review and diligence, merged under standing watch rules. No human reviewers requested. Preserve current state with backups before any host migration; avoid restarting active runs. First migrate one idle host, then io, iobook, iobox and axat-vps using existing supported install paths and channel controls. A newer-than-stable runtime or failed smoke check holds that host. Never run two servers against one data directory. Keep automatic worktree cleanup disabled.
6. Release: Axstack source changes invoke its standing release/install rule and tag-triggered publish workflow, with reinstall on all four named hosts after T3 meets the new floor. Haoshoku release and install on the same hosts are proposed for this checkpoint. Human npm stage approval remains human-only. No unrelated full-system upgrade or broad Haoshoku setup rerun merely to apply these changes.

Acceptance: fresh supported setup chooses stable; managed old defaults migrate; repeated setup stays stable; capability check reports a stable prerequisite; Omarchy desktop matches the imported current palette once, or a precise manual import checkpoint remains open; source and live verification are separately reported; no unverified host is marked complete.

Design: reuse existing installer/version/launcher seams and the existing Omarchy palette and supported T3 custom-theme import. No additional runtime, scheduler, palette converter or state store.

Open execution facts: exact running versions/service channel on other hosts; stable package availability; supported one-time desktop theme import with Local environment disabled; phone version. Resolve by read-only inspection before affected writes. A missing compatible client theme path blocks that slice rather than inventing an unsupported workaround.

Verification map: Axstack uses verify-axstack and its capability fixtures; Haoshoku extends existing Bun fixtures for workspaces/primary app, install_user_scripts, configure_axstack, t3_tailscale, configure_t3_code_server and t3_desktop_preflight, plus CLI/package and live appearance checks. Proposed no separate verify-haoshoku skill for this bounded change, subject to both adviser receipts. Haoshoku base is /root/dev/Haoshoku (stable); the lowercase checkout is stale. Each repository owns its stable version floor to avoid PR ordering dependency.
