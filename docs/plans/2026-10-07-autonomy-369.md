## Evidence and operational constraints

- T0 reads installed 0.27.4 and pinned source owner files, records hashes and existing native own-run settlement/readback receipts. Lack of idempotency, in-flight or never-issued-after-interruption proof is UNKNOWN, not an inferred failure or pass.
- The confirmed source silence ambiguity is sufficient for T1. No new runtime mechanism is built to collect data. Additional settlement/lost-reply prose edits beyond the approved narrow rule require demonstrated baseline gaps; otherwise leave those surfaces alone.
- T3 candidate canaries read exact pinned-checkout files using the spec's test-only override. Receipts echo actual file hashes, candidate SHA, provider/model/effort and native IDs. No installation or live home config changes during development.
- Use configured T3 execution roles with isolated detached checkouts. Any necessary independent canary driver uses an explicitly bound top-level T3 test thread under standing run-owned thread authority; no harness-native agent and no untracked helper daemon. Record exact roles, ownership and bounded scenario before launch.
- Only run-owned disposable resources may be mutated. Native schedules are short-lived scenario resources, not an Axstack scheduler. Preserve evidence, settle/retire eligible canaries, delete exact owned schedule IDs and verify absence. Never mutate actual user-taken-over or foreign resources or T3 databases.
- First settlement records intent but does not consume the extra-call allowance. Consume that allowance immediately before the additional call; an ambiguous interruption must not restore it. Cleanup re-invocation cannot create a second allowance path.
- Normal uninterrupted driver control flow can witness a first call. After interruption, no known native proof establishes never-issued; preserve UNKNOWN/hold and report once. R tests classification only, not production proof. User approved this explicit limitation; required evidence was not waived.
- User chose labelled simulated transport failure plus native settlement/readback checks. No actual outage is required or claimed. An idempotency observation for one unchanged completion does not prove race safety; unresolved in-flight effects still hold.
- Unavailable required N/R/S evidence holds its acceptance and release; no task may silently weaken evidence standards. A scope reduction needs an approved revised baseline.
- Default native runtime and safety instructions remain in force; the candidate-file override applies only inside isolated canaries. No new writer recovery, launch/send retry, model substitution or general retry engine.
