# Axstack-owned workflows and host retirement

Status: authorized by the user's 2026-09-13 request to replace the remaining
engineering workflows with Axstack, followed by explicit selection to retire
all other user-installed skills. The v1 spec remains the baseline; this
amendment expands workflow coverage and authorizes reversible host retirement.

## Outcome

Use Axstack alone for alignment, specifications, tasks, implementation,
research, authored and colleague PR review, PR maintenance, documentation,
visual explanations, and handoffs. Preserve useful principles without a
runtime dependency on another skill collection. Paseo, model harnesses,
GitHub/gh stack and optional Linear/Hermes integrations remain tools.
Retiring specialist skills does not claim their domain capabilities are
reimplemented by Axstack. Harness system skills are not user-installed assets.

## Accepted contracts

- Current chat drives; persistent Opus medium PR owner; Sol medium ordinary
  author; two independent Sol/Opus medium final reviewers receive the same
  six-angle brief. Strict TDD, exact-revision evidence and accepted high-stakes
  Fable/pair rules remain. No provider substitution without user decision.
- Research is independently callable. Verify primary sources and code, cite
  material claims and limitations, save the requested artifact. One bounded
  question does not require a panel or spec approval. Fan out distinct questions
  only when useful; no automatic research team or implementation.
- Peer review accepts PR description, linked issue and repository requirements
  as intent; it does not demand an Axstack-created approved spec. Missing or
  contradictory intent makes requirements coverage incomplete. Both reviews
  stay independent; the owner validates findings. Submit only within user
  authority, with report-only honored and exact-head readback/idempotency.
- Adopt an existing authored PR by recording its accepted maintenance scope,
  actual head/base and current ownership. Monitoring-only never authorizes
  repairs or replies. Writable babysitting requires author ownership and
  reviewed code plus exact reply text before authorized publication.
- One owner and one watch per PR. Keep native Paseo monitor and health-check
  mechanisms, event deduplication, initial handshake and restart reconciliation.
  Healthy ticks do not wake the driver. A 24-hour default deadline applies to
  all task-owned timers, including open PRs; no silent renewal. Human merges
  by default. Merge-ready is an observed state, not a guarantee against drift.
- Axstack owns compact handoffs, resume reconciliation, routing and lifecycle
  instructions. No dependency on another installed skill or private host path.
- Axstack owns source-backed prose and requested visual explanations. Preserve
  requested format/theme and verify actual rendered behavior where applicable;
  report unavailable evidence. Publication requires its own authority.

## Run audit and planning amendment (user-directed)

The user added run self-improvement/auditing, Fable 5.1 involvement in
specification/design/decision work, and preference for parallel subagent-driven
execution. They explicitly selected tested, reviewed improvement PRs with human
merge, not automatic skill mutation.

- Fable 5.1 participates in spec creation/revision, solution design and
  consequential decisions, including initial choices that are not disputed.
  Cache accepted receipts while their evidence/scope is unchanged; executing
  the settled plan does not require another consultation for every small step.
- Prefer bounded parallel workers for independent tasks and retain exclusive
  writer ownership and resource isolation. Measure useful decomposition, not
  raw agent count. Dependencies, shared mutable resources or lack of a useful
  independent subtask justify serial work.
- Enable an independent Luna max run auditor after substantive runs and useful
  checkpoints. Inspect accepted scope, plan and decision records, actual source
  revisions, tests, reviews and execution evidence. The auditor writes reports
  only; its evaluation does not replace PR review or human authority.
- Track acceptance passed/failed/unverified with denominators; plan deviations
  and their authorization; Fable decision coverage; TDD and independent-review
  evidence; rework causes; avoidable interventions; useful parallelism; and
  actual resource use only where provider receipts make it measurable.
  Keep process adherence, product outcome and evidence completeness separate.
- Missing evidence stays UNKNOWN. Never invent costs, retroactive TDD, success
  or causality. Audit records are local/private by default; public proposals use
  sanitized evidence, not raw private traces or credentials.
- Improvements require a demonstrated weakness, bounded hypothesis, a regression
  scenario plus unchanged holdout checks, independent review and a proposed PR.
  Human merges; no automatic self-editing or silent changes to expectations.

Hermes' official self-evolution repository provided conceptual comparison:
https://github.com/NousResearch/hermes-agent-self-evolution (read 2026-09-13).
Its README distinguishes execution traces, candidate evaluation and reviewed
PR delivery. Axstack implements its own prompt workflow; no Hermes/DSPy/GEPA
runtime, source copy, or external analytics dependency is added.
