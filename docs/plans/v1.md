# Axstack v1 Implementation Plan

For agentic workers: execute only your assigned task with strict TDD. The user selected Paseo fanout using OpenCode Muse Spark 1.3 Free; no other model or nested team is authorized for this build.

**Goal:** Ship a self-contained installer and chat skill bundle implementing the approved Axstack lifecycle.
**Architecture:** Paseo is the runtime. The CLI installs/checks owned assets; prompt skills own workflow decisions. Shared references carry review, authority and evidence contracts.
**Tech stack:** Bun >= 1.3.14 JavaScript, `bun:test`, GitHub gh stack, Markdown skills, JSON profile assets. Narrow approved exception: node:fs and node:fs/promises (Bun-implemented built-ins); no Node.js runtime. Avoid dependencies unless a concrete need is reported.
**Spec:** `docs/specs/v1.md`, originating in GitHub issue #1.

## Global constraints

- Linux and macOS; Windows through WSL. Claude/Codex primary, OpenCode/Grok capability targets with explicit verification status.
- Chat drives execution; CLI installation/setup only. No separate daemon or workflow state machine.
- One execution host per run, default two active PRs, 24-hour bounded monitoring.
- Current chat driver, Fable advisor, Opus PR owners, Sol authors, independent Opus and Sol final reviewers.
- Exactly two final reviewers, identical six-angle briefs, non-authors, immutable revision evidence.
- Strict red/green/refactor for implementation. Behavioral evidence for skills; structural tests alone cannot prove instruction following.
- Prompt-only serious-risk escalation; human merge default; no model substitution without user approval.
- Linear native document first, explicit Markdown alternative; report-only cheap sync agent, driver updates.
- This repository uses GitHub issues for its own spec/work tracking.
- Do not mutate host configuration, credentials, schedules, or unrelated assets in tests.

## Frozen stream boundary

| Producer | Consumer | Contract |
| --- | --- | --- |
| Workflow author | Installer | `skills/axstack*/SKILL.md`; recursive supporting files within each skill folder, no escaping symlinks |
| Workflow author | Installer | `profiles/paseo.json`: `{ "version": 1, "agentProfiles": [...] }`, namespaced `axstack-*` IDs with provider/model/modeId/thinkingOptionId/notes |
| Installer | Workflow docs | `axstack install`, `axstack check`, `axstack uninstall`; flags documented by installer, explicit target directories supported |
| Both | Integration | `bun test` discovers `tests/**/*.test.js`; no test mutates real user state |

Package owner declares bin `axstack: bin/axstack.js`, type module, Bun floor and scripts. Package files include bin, src, skills, profiles and user documentation. Workflow tests must run without third-party dependencies or installer modules. Each stream can be reviewed independently; combined package verification follows integration.

## Task 1 — Safe installation and setup

Owned files: `package.json`, `bin/axstack.js`, `src/**`, `tests/installer/**`, `docs/installation.md`, installer-specific fixtures.
Do not create production skill/profile content; tests create temporary fixture bundles matching the frozen contract.

- [ ] Write failing CLI/file-behavior tests using `bun:test` and `mkdtemp`: install into explicit temporary skill destinations; repeated install is idempotent; unrelated files survive; edited owned files are detected and preserved; uninstall removes only unchanged owned assets.
- [ ] Execute the tests against a non-implementing stub and record actual intended behavioral failures, not just module import errors.
- [ ] Implement minimal install/check/uninstall with a small ownership manifest. Validate paths and assets before mutation; reject traversal and symlink escapes; never overwrite unknown files or blindly remove directories. Recover safely from partial failures and report them.
- [ ] Add tests first for Paseo profile merging: preserve custom profiles and unrelated daemon fields, handle absent config, reject malformed config without mutation, retain user edits rather than silently replacing them, remove only unchanged Axstack-owned profiles on uninstall.
- [ ] Implement the profile merge as installation bookkeeping. No escalation gate, run scheduler, model calls, or execution state engine in code.
- [ ] Check actual CLI/tool availability using injected command execution for tests; report gh stack and Paseo gaps. Document that a host binary probe cannot prove each agent's Linear MCP access or model quota. Skill prompts perform session preflight.
- [ ] Verify supported harness skill locations against primary docs/local CLI help. Provide explicit destination override where automatic discovery is unverified, especially Grok. No invented compatibility or credential handling.
- [ ] Add a package smoke test: pack into temporary output, inspect bundled assets, run installed CLI there. Full actual bundle smoke runs again after Task 2 integration.
- [ ] Run targeted tests and diff check, make granular local commits, and return exact revision, red/green evidence, commands/results, limitations, and changed files. No push/PR/host install.

Example observable contract (author may choose function signatures): execute the real CLI with an explicit temporary home/target and a fixture bundle; assert an unrelated sentinel is byte-identical, the expected installed SKILL.md is readable, second install has no changes, a user-edited owned asset survives uninstall, and an escaping bundle is rejected before any target write. This behavioral boundary is more important than prescribing internal modules.

## Task 2 — Owned workflow skills and role profiles

Owned files: `skills/**`, `profiles/paseo.json`, `tests/workflows/**`, `docs/workflows.md`.
Read writing-for-agents/skill-creator guidance if useful, but shipped content must have no machine-specific or upstream-skill dependencies.

Do not claim behavioral red without observed evidence, and do not start production skill behavior until the baseline/evaluation decision returns. You may develop structural fixture tests and profile data tests while waiting.
- [ ] Add tests first for parseable frontmatter, packaged relative references, valid profile schema and role diversity, and absence of external absolute skill dependencies. Label these structural checks, not behavioral proof.
- [ ] Author compact phase skills: `axstack`, `axstack-align`, `axstack-spec`, `axstack-tickets`, `axstack-implement`, `axstack-review`, `axstack-watch`. Keep phase-specific instructions progressively loaded. Supporting references must travel with installed assets; use sibling Axstack skill references only where the installer guarantees all are present.
- [ ] Include templates for approved-spec identity, capability/internal task mapping, compact handoff, candidate review brief, review evidence, and drift reports. Records support Paseo rather than duplicating its runtime.
- [ ] Encode persistent owner-per-PR, exclusive writers, author repair continuity, dependency queue, gh stack coordination, and restart reconciliation. A worker does not become a second global driver.
- [ ] Encode strict TDD, exact-revision independent Sol/Opus review, all six angles, no cross-reading initial findings, no vote-based resolution, prompt-only urgent escalation and optional guarded Hermes relay with Paseo fallback.
- [ ] Encode Linear-native-doc MCP preflight per session, explicit Markdown fallback selection, report-only checker, driver-owned updates, merged-plus-accepted Done, and affected-work spec-change hold.

- [ ] Run structural/profile tests, verify references, make granular local commits, and return exact revision, behavioral evaluation status, limitations, and changed files. No external writes/host install.

Driver coordinates after Tasks 1 and 2. Source repairs return to their original Muse authors; the current driver performs independent source review without launching Claude/Codex children.

- [ ] Review each stream against the spec and code quality; resolve substantive findings through its author and refresh the reviewed revision.
- [ ] Integrate the independent branches into a stack through gh stack; main remains the bootstrap documentation base and is not merged automatically.
- [ ] Run combined Bun tests, fixture-only installation/check/uninstall, package contents and neutral-directory CLI smoke. Validate no unpublished package or skill path assumption.
- [ ] Execute behavioral scenarios in fresh Muse evaluator sessions and record case inputs, expected outcomes, actual outputs and limitations. Do not substitute keyword matching for behavior.
- [ ] Add missing integration tests before fixes; run Linux locally and configure macOS/Bun-floor CI if feasible. Report unavailable OS/harness execution as unverified rather than passing.
- [ ] Write public usage/compatibility documentation from actual evidence. Root source changes, if needed, are delegated to Muse.
- [ ] Submit reviewed candidate PR(s) using gh stack with test evidence and unresolved limitations. Human retains merge/release control. No npm publish, live installation, or recurring schedules for this build without separately applicable authority.
