## Required amendments

1. **`skills/axstack-review/SKILL.md` must be named among the files updated in the same change (spec:15–19, 52, 119–121).** The spec says "Review modes follow `skills/axstack-review`" and then publishes an owner-synthesized `COMMENT` review and runs with no separate `axstack-owner`. The installed skill contradicts both and the automation session will load it: `SKILL.md:261–264` allows submission "only for a complete `APPROVE` or `REQUEST_CHANGES` verdict" (both prohibited by spec:45–46), `SKILL.md:249–255` says report-only writes nothing to GitHub, and `SKILL.md:62–69` says standalone peer review or watch adoption "materializes `axstack-owner`". Amend spec:15–19 to add `skills/axstack-review/SKILL.md` (Standalone owner, Authorized submission) to the same-change list, with the `COMMENT` branch stated there exactly as spec:119–123 states it. Without this the peer-PR branch is unreachable under the loaded skill.

2. **The driver must persist the fingerprint the precheck observed, never a recomputed one (spec:105–107, 154–156).** The precheck hashes state at time T and exits 0; the driver "writes `cursor.json` after each processed tick", but the spec does not say where that hash comes from. If the driver recomputes at end of run, a push or comment that lands between the driver's read and its cursor write is folded into the stored hash, the next precheck compares equal, and the event is never handled. This conflicts with the spec's own dedup/no-lost-event intent (acceptance 4) and with `docs/specs/v1.md:181` ("Wake work when CI/review state changes") and `skills/axstack-watch/SKILL.md:98` (a handled wake acknowledges its event). Amend: the precheck writes the observed fingerprint to the sidecar (for example `cursor.json.observed`), and the driver promotes exactly that value to `last` after the processed tick. Add to acceptance 4 or 5: a change made while a run is in progress is processed on the following tick.

3. **Pin `--limit` on the three searches (spec:38–40, 104).** `gh search prs --help`: `-L, --limit int … (default 30)`. The measured account already has 18 open own PRs; a 31st result is silently dropped from the fingerprint and never watched. Amend: `--limit 100` (or higher) on every search, and treat a result count equal to the limit as an `error` line in `precheck.log`.

4. **Classify `gh pr checks` exit codes as data, not failure (spec:103–110).** `gh pr checks --help` documents exit 8 for pending checks, and `gh help exit-codes` documents exit 1 for any failure, which `gh pr checks` uses when a check has failed. A precheck that treats "gh fails" as any non-zero exit logs a red check — the very event the own-PR watch exists for (prior amendment 3) — as `error` and skips the run. Amend: only exit 4 (authentication) and command or network errors are `error`; exits 0, 1 and 8 from `gh pr checks` are check state and enter the hash (use `--json bucket,name`). Extend acceptance 2 with: exit zero on a synthetic failing check at an unchanged head.

## Driver proposal

AGREE — replace "outside the allowlist a PR still receives report-only review" with "discover and record only; no model work and no escalation". One reason: an escalation is only useful where the automation could otherwise act, and outside the allowlist it can neither push nor publish, so the user gains nothing beyond GitHub's own review-request and mention notifications, while each changed external PR currently costs two reviewer sessions plus a Luna max gate against ~17 PRs it cannot touch. To make "no model work" literally true, the precheck (not the driver) should write the full discovery list to the sidecar and hash only PRs in allowlisted repositories, so external `updatedAt` churn no longer launches the session at all; the driver copies the discovery snapshot into `progress.md` on its next real tick. This also removes ~17 `gh pr checks` calls per tick from the precheck. Discovery stays everywhere, as settled.
