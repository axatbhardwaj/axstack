# Bounded live fleet verification (later C3/C6)

Run only under the driver's recorded live/host authority. C3a ships this procedure;
it does not execute it or enable routing. Offline fixtures and source inspection
cannot establish live eligibility. Use [Fleet dispatch](fleet-dispatch.md) for
receipt fields, [T3 runtime](t3-runtime.md) for native lifecycle, and the repository
verify-axstack recipe for separate offline coverage. Never mix live credentials or
network into that isolated recipe.

## Prepare one owned attempt

Record run key, origin T3 thread link, operator, allowed origin/targets, role/model/
options/full-access, repository/project identities, exact candidate/base, explicit
start/end times and a maximum of one harmless nonwriter per distinct route config.
No overload stress, installation, global policy edits, raw provider CLI or production
writes belong to this procedure. Exclude any unverified route from enabled coverage.
No top-level thread without an explicit new-thread request.

Create a fresh 0700 scratch outside HOME on each participating host; record each
literal path with hostId/environmentId. Before use validate owner, realpath and
no symlink. Use a separately owned persistent evidence folder on origin and target,
outside scratch selected for deletion. Put only a tiny fixture README/candidate in
an explicitly provisioned test project. Record its root HEAD/status/all refs before
and after; no shared project or unknown ignored artifacts may be cleaned.
Use native T3 worktree isolation for candidate reviewers; no shell child checkouts.

Save a coverage row for every directed origin→target and materially distinct
provider/model/options/runtimeMode/project/isolation/browser/session configuration.
Record both endpoint T3/Axstack versions, exact installed skill hashes, config
schema/digest, native-balancer client setting and link expiry. Reuse evidence only
with a recorded equivalence argument; direction/version/project/session differences
require their own check. Do not expose credentials in this matrix.

Suggested harmless nonwriter brief: name its key, target-only private evidence
path, pinned candidate/base, read-only fixture question and exact final
AXSTACK-DONE marker; forbid tracked/untracked project writes, children, forge,
install/config edits and html_render. No worktree author or coordinator is part
of the nonwriter check. Save the observed dispatch response rather than a worker's
claim about how it was launched.

For terminal negative controls use offline saved copies with one changed fact
(stale run, question, pending child, wrong env/project/settings/path). Do not create
real denied prompts, disconnected workers or orphaned production tasks just to
exercise a guard. Live submission ambiguity, cancellation, provider continuation
and question handling remain separate UNKNOWN rows unless actually observed in
an authorized owned context. Never infer their success from an offline negative.

## Remote authors stay disabled

C3b's all-refs-unchanged pilot failed on T3 checkpoint refs. Do not rerun, waive
or enable that coordinator in C3a/C6 nonwriter verification. Direct remote worktree
authors are ineligible on T3 v0.1.5. Local isolated authors remain the fallback.
Any future separately authorized C3b investigation must prove every F4 gate in the
approved baseline: target local isolation and exact base, nested completion,
same-author repair/new-run origin wake, question/answer/resume, approval boundary,
cancellation/failure/orphan propagation including owned disconnected cases,
unchanged root HEAD/status/all refs, exact retrieval and owned retirement. Record
all nested IDs and both versions. Unknown stop forbids replacement. No production
enablement without all gates and accepted scope; no silent all-refs exception.

## Cleanup and receipt

For each owned remote reviewer, read exact target thread/run/ownership again.
Archive evidence on origin, verify its digest and read it back, then settle on
target and verify settled:true before removing that recorded disposable checkout.
Retain user-taken-over, changed, active, unknown or ambiguously owned resources.
Driver alone owns forge publication, PR links/watch and merges. No worker watches.

For each scratch path, validation must succeed first: exact created literal path,
no symlink, realpath equality, current ownership and 0700 mode. Finish validation
successfully, then perform deletion in a separate sequential call on that same
host/path. Never parallel validation/deletion, ignore failures, glob shared paths,
clean by age or delete unknown ignored artifacts. Confirm scratch absence and
persistent evidence survival; record retained resources with a named hold.

Return rows as PASS/FAIL/UNKNOWN/N/A with command/native-call evidence and exact
versions/config/candidate hashes. Summaries are counts only, never aggregate
permission. List every omitted config/host/gate and its owning phase. C4 owns
personal routing policy/Haoshoku live changes; C6 owns deployment and the complete
live matrix. Nothing here declares a deployed routing switch.

Rerun affected rows after routing/helper/receipt releases, either endpoint's T3
version change, link replacement/expiry/access change, project/provider/model/
options/runtimeMode/session/browser change, config digest or policy change, and
before C6 acceptance. A failed bounded attempt retains evidence; reconcile and
repair within authority before one new explicit attempt. Never create a scheduler,
state machine or recurring task to make verification run itself.
